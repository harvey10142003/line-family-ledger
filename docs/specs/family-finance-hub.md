## 0. 一句話結論

把「宇果記帳」從「記每天花了什麼」升級成「全家的錢都在這裡」：**所有帳單、存摺照片、Excel 不分類直接丟給 LINE，AI 自己認出是哪家銀行、哪張卡、哪一期、誰的，解析、去重、對帳後記下來；數字一律由程式算，AI 只負責辨識和說明。**
**但上線前一定要先補一個資安洞**（第 6.1 節）：現在記帳簿的 API 只看前端送來的 LINE userId 就相信，沒有驗證身分。存信用卡、貸款資料之前必須先修。

**推薦 MVP**＝P0 資安前置 ＋ P1 資產負債骨架（含文字記帳補強與一句話建轉帳）＋ P2「無腦丟件」中樞（LINE 傳檔／照片＋LIFF 多檔上傳，處理電子帳單 PDF 和紙本存摺照片），約 **33.5 人日**。「每天自動從 Shark 和 Apple 的 Gmail 抓帳單」列為正式功能，放**第二期第一項**（約 7 人日，MVP 做完就接），做法推薦「Gmail 篩選器自動轉寄到家庭專屬收件地址」＋「Apps Script 一次性回補舊信」，**不採用伺服器端 Gmail OAuth**（3.8 節）。

## 1. 現況盤點（以 `55842f5` 的程式為準）

### 1.1 現有資料表（`prisma/schema.prisma`）

| 表 | 用途 | 跟「財務全貌」的關係 |
|---|---|---|
| Family / FamilyMember | 家庭與成員（LINE userId 綁定，角色 OWNER/MEMBER） | 成員沒有「真實姓名」欄位，沒辦法對到帳單上的戶名 |
| Category | 13 種預設分類，收入／支出 | 可沿用 |
| Transaction | 每一筆收支；帶 accountId **或** creditCardId；`isShared` 共同／個人；`source`=TEXT/PHOTO/MANUAL/RECURRING | 沒有「從哪份文件匯入」「跟哪筆是同一筆」的欄位；沒有外部參考號 |
| Account | 現金／銀行／電子錢包／其他，期初餘額，餘額＝期初＋收－支＋轉入－轉出 | 沒有「誰的帳戶」，沒有定存／證券類型，沒有帳號末四碼 |
| CreditCard | 額度、結算日、繳費日 | 沒有「誰的卡」、卡號末四碼、發卡行；**沒有帳單（每一期）的概念** |
| Transfer | 帳戶 → 帳戶轉帳，不算收支 | **只能帳戶轉帳戶，不能「銀行繳卡費」**（卡不是 Account） |
| Budget / SavingsGoal / RecurringRule | 預算、儲蓄目標、固定收支 | 可沿用 |
| Receipt | 收據圖片 | 有表但沒在用（圖片沒存） |
| InviteLink | 家庭邀請 | 不相關 |

### 1.2 已有功能

- 文字記帳（Gemini 解析，多細項拆筆、付款方式、商家進備註）
- 拍收據記帳（多品項時拆成多筆）
- **PDF 帳單匯入**（`message-file.ts`：傳 PDF → Gemini 解析多筆 → Quick Reply 確認 → 寫入）
- 帳戶餘額、帳戶間轉帳、信用卡本期已用額度、繳費前 3 天提醒
- 整體／分類預算、儲蓄目標、固定收支、共同／個人分帳、近 6 月趨勢、月報 Flex、CSV 匯出

### 1.3 缺口（要做成「中樞」缺的東西）

1. **沒有負債**：房貸、車貸、信貸、親友借款完全沒地方放；信用卡只有「本期用多少」，沒有「已出帳未繳多少」。
2. **沒有歸屬**：帳戶和卡不知道是 Shark 的、Apple 的、還是共同的；也沒有「對方可不可以看」。
3. **繳卡費會被重複算**：現在繳卡費只能記成一筆支出（因為 Transfer 不能轉到卡），消費本身又已經記過一次 → 同一筆錢算兩次。
4. **匯入不去重**：PDF 匯入是直接 `createMany` 全部寫入，同一份帳單丟兩次就記兩次；拍照記過的消費，帳單再進來也會重複。
5. **加密 PDF 打不開**：多數銀行電子帳單有密碼，現在的流程直接把 PDF 丟給 Gemini，加密檔一定失敗。
6. **沒有文件紀錄**：丟進來的檔案不保存、沒有處理狀態，失敗了也只回一句「解析失敗」。
7. **沒有淨資產**：只有「總資產卡」（帳戶餘額加總），沒扣負債、沒有每月快照，看不到走勢。
8. **資安基礎不夠存這種資料**：見 6.1。

## 2. 資料模型提案

> 原則：**新增表為主，不改舊欄位的意思**（expand 模式，舊資料照常可用）。金額一律 `Decimal(14,2)`，台幣為主，外幣交易存原幣＋台幣。

### 2.1 歸屬與可見範圍（套在帳戶、卡、負債上）

```
ownerMemberId   String?    // null = 共同；有值 = 某位成員個人的
visibility      Visibility // 對「其他家庭成員」的可見程度
enum Visibility { FAMILY_FULL, FAMILY_TOTAL_ONLY, OWNER_ONLY }
```
- `FAMILY_FULL`：全家都看得到明細（共同帳戶預設）
- `FAMILY_TOTAL_ONLY`：對方只看得到餘額或欠款總數，看不到每一筆（個人帳戶建議預設，見 D2）
- `OWNER_ONLY`：對方完全看不到，也不算進「家庭淨資產」（只算進本人的淨資產）

FamilyMember 加：`legalName`（帳單上的戶名，例如「施允瀚」，用來比對歸屬，加密存放）。

### 2.2 資產帳戶（擴充現有 Account）

- `type` 增加：`TIME_DEPOSIT`（定存）、`SECURITIES`（證券）、`INVESTMENT`（基金／保單價值等）、`CRYPTO`（虛擬資產；Shark 信箱有 MAX 交易所出金通知，代表有這類帳戶）、`DIGITAL_BANK`（純網銀，如樂天、將來，本質是 BANK，可只用 institution 區分，實作時二擇一）
- 帳戶加 `purpose`：`FAMILY`（家庭帳）／`BUSINESS`（公司或企業網銀，例如中信企業網銀）——BUSINESS 帳戶預設**不算進家庭淨資產與收支**，只留紀錄
- 新欄位：`institution`（銀行代碼／名稱，例如 808 玉山）、`accountLast4`（**只存末四碼**，絕不存全碼）、`currency`、`ownerMemberId`、`visibility`
- 證券、基金這種「價值會漲跌」的帳戶，餘額不是加減算出來的，而是**估值**：新表 `AccountValuation(accountId, asOfDate, value, source)`，每月手動填一次或從對帳單讀（見 D7）。

### 2.3 信用卡（擴充 CreditCard ＋ 新增帳單表）

- CreditCard 加：`issuer`（發卡行）、`cardLast4`、`ownerMemberId`、`visibility`、`isSupplementary`（附卡，附卡消費算正卡人的負債但可標記使用人）
- 新表 **`CardStatement`**（每一期帳單一列）：`cardId / periodStart / periodEnd / statementDate / dueDate / newBalance（本期應繳）/ minimumDue（最低應繳）/ paidAmount / status(OPEN, PAID, PARTIAL, OVERDUE) / documentId`
  - 唯一鍵：`(cardId, statementDate)` → 同一期帳單只會有一列（冪等的基礎）
- 信用卡欠款拆兩段看：
  - **未出帳**＝結算日之後刷的，還沒進帳單（用 Transaction 加總）
  - **已出帳未繳**＝最近一期 `newBalance − paidAmount`

### 2.4 負債（新表）

```
Liability
  id, familyId, ownerMemberId?, visibility
  kind          MORTGAGE 房貸 | CAR 車貸 | PERSONAL 信貸 | FAMILY 親友借款 | OTHER
  lender        貸款銀行／債權人（親友就寫名字）
  principal     原始本金
  annualRate    年利率（可變利率要能改，改了記歷程）
  termMonths    期數
  startDate     首次還款日
  paymentDay    每月還款日
  method        EQUAL_PAYMENT 本息平均 | EQUAL_PRINCIPAL 本金平均 | INTEREST_ONLY 寬限期 | FREE 無固定（親友）
  gracePeriodMonths 寬限期月數
  payFromAccountId  從哪個帳戶自動扣
  currentPrincipal  剩餘本金（以「最近一次對帳值」為準，程式也會推算，兩者不同時提示）

LiabilityRateChange(liabilityId, effectiveDate, annualRate)
LiabilityPayment(liabilityId, paidAt, total, principalPart, interestPart, feePart, transactionId?, transferId?)
```
- 每期還款**拆兩半**：本金部分＝把錢從銀行搬去還債（不是支出，是資產減少同時負債減少）；利息與手續費＝真正的支出（記進「貸款利息」分類）。
- 親友借款通常沒有利率和期數：`method=FREE`，只記本金和每次還多少。
- 加 `direction BORROWED | LENT`：BORROWED＝我們欠別人（負債）；LENT＝別人欠我們（應收，算資產）。「借小明 5000」就是一筆 `LENT` 的 Liability，用同一張表，不另開應收表。

### 2.5 「不是支出」的錢：轉帳、繳卡費、還本金

現在 Transfer 只能帳戶 → 帳戶。改成通用的「搬錢」：

```
Transfer（擴充）
  fromAccountId        必填
  toAccountId?         轉到另一個帳戶
  toCreditCardId?      繳卡費（同時把 CardStatement.paidAmount 加上去）
  toLiabilityId?       還貸款本金
  kind  ACCOUNT | CARD_PAYMENT | LOAN_PRINCIPAL
  (三個 to 只能填一個，程式檢查)
```
完整的轉帳種類、文字建轉帳、撤銷與對帳見 **3.10**（3.10 的模型取代這裡的簡版）。
**規則：支出只在「消費發生」時算一次。** 刷卡吃飯 → 記一筆支出（掛在卡上）；月底銀行扣卡費 → 只是 Transfer(CARD_PAYMENT)，報表不算支出。

### 2.6 文件（丟件中樞的核心表）

```
Document
  id, familyId, uploadedByMemberId
  channel        LINE_FILE | LINE_IMAGE | LIFF_UPLOAD | EMAIL_FORWARD | GMAIL_SCRIPT
  emailMessageId?  原信的 Message-ID（同一封信從兩條路進來也只算一次）
  emailFrom?, emailSubject?, emailBodySummary?  信件內文讀到的摘要數字（應繳、截止日），PDF 打不開時先用
  sha256         原始檔案內容雜湊（同檔重丟→直接認出）
  imageSetId?    LINE 一次傳多張照片時的群組 id（存摺多頁）
  mime, sizeBytes, originalName
  storageKey?    加密後的原檔位置（保存期見 D4）
  status         RECEIVED → NEEDS_PASSWORD → PARSING → NEEDS_CONFIRMATION → IMPORTED
                 或 DUPLICATE / FAILED / IGNORED
  failReason     給人看的失敗原因（「密碼不對」「看不出是哪家銀行」「照片太糊」）
  docType        CARD_STATEMENT | BANK_STATEMENT | PASSBOOK_PAGE | RECEIPT | LOAN_STATEMENT | INVESTMENT_STATEMENT | SCREENSHOT | SPREADSHEET | UNKNOWN
  institution?, last4?, periodStart?, periodEnd?, statementDate?
  ownerMemberId?, ownerConfidence (0~1), ownerEvidence (JSON：哪些線索)
  semanticKey?   例如 "card:台新:1234:2026-10-25"（不同檔案但同一期 → 也認得出重複）
  parsedJson     解析結果（遮罩後）
  createdAt, processedAt, expiresAt（原檔刪除時間）

@@unique([familyId, sha256])
@@unique([familyId, semanticKey])
@@unique([familyId, emailMessageId])

MailSenderRule（寄件人白名單，第 3.8 節）
  familyId?（null＝系統內建）, institution, fromAddress, subjectPattern, docKind, action(PARSE | IGNORE | MARK_BUSINESS), isActive
```

Transaction 加：`documentId?`、`externalRef?`（帳單上那一行的指紋，見 4.2）、`postedAt?`（入帳日，跟消費日 paidAt 分開）、`originalCurrency? / originalAmount?`、`matchGroupId?`（被合併的同一筆）、`receiptGroupId?`（同一張收據拆成的多筆）。

### 2.7 每月淨資產快照（新表）

```
NetWorthSnapshot(familyId, month "YYYY-MM", scope: FAMILY | MEMBER, memberId?,
                 assets, liabilities, netWorth, breakdown JSON, createdAt)
@@unique([familyId, month, scope, memberId])
```
- 每月 1 號 08:30（台北）由 cron 依「上個月最後一天」的餘額算一次並存下來，之後就算改了舊資料，歷史點也不會跳（要重算可手動按）。
- 計算全部用程式：資產＝現金＋銀行＋定存＋最近一次證券／投資估值；負債＝卡未出帳＋已出帳未繳＋各貸款剩餘本金＋親友借款。

## 3. 資料怎麼進來

### 3.1 「無腦全部丟」：統一丟件入口

**一個原則：不管從哪裡丟、丟什麼，都進同一條處理線（Document pipeline）。**

```
LINE 傳檔／照片 ─┐
LIFF 多檔上傳 ───┼─→ 建 Document（算 sha256，重複就停）
轉寄信箱（二期）─┘        │
                         ▼
                ① 打不開？要密碼 → 試已記住的密碼 → 都不行才 LINE 問一句
                         ▼
                ② 辨識：文件類型／哪家銀行／哪張卡或哪個帳戶／哪一期／誰的
                         ▼
                ③ 解析成一行一行（金額、日期、摘要）→ 程式驗算（加總、餘額鏈）
                         ▼
                ④ 跟既有資料比對：同一期帳單？同一筆消費？繳卡費？
                         ▼
                ⑤ 信心高 → 自動入帳，LINE 回一句摘要
                   信心不足 → LINE 問一句（只問最關鍵的那一題）
                         ▼
                ⑥ 文件狀態頁看得到每份文件現在在哪一步
```

三個入口：

| 入口 | 怎麼用 | 備註 |
|---|---|---|
| **LINE 直接傳** | 在「宇果記帳」聊天室傳 PDF、照片、Excel、截圖；手機上收到帳單信，在郵件 App 點附件 →「分享」→ LINE → 宇果記帳 | 現成的 file / image 事件就能接。LINE 一次傳多張照片時會帶同一組 imageSet（存摺多頁可以自動湊成一份）。**注意**：LINE 傳照片預設會壓縮，存摺照片建議選「原始畫質」（未驗證壓縮後對 OCR 的影響，MVP 實測） |
| **LIFF 多檔上傳** | 記帳簿新增「丟件」分頁，一次選多個檔案拖進去／從手機相簿多選 | 電腦上整理一堆舊帳單最快；這裡也是看處理狀態的地方 |
| **每天自動從兩人 Gmail 抓**（二期第一項，正式功能） | 用 Gmail 篩選器自動轉寄到家庭專屬收件地址（推薦），或在本人帳號裝 Apps Script 定時送件 | 設定一次後每月 0 操作；方案比較、白名單、每日詢問見 **3.8** |

### 3.2 自動辨識類型與歸屬

**辨識分兩層：先用程式規則，規則認不出才叫 Gemini。**

1. **文件類型與銀行**：
   - 程式先看：檔名、PDF 中繼資料、文字內容的關鍵字（「信用卡帳單」「本期應繳總額」「存摺」「交易明細」、銀行名、銀行代碼）、Excel 欄位名稱。
   - 規則認不出 → Gemini 回傳結構化 JSON：`{docType, institution, last4, periodEnd, holderName}`（只回這幾個欄位，不讓它算數字）。
   - 同一家銀行認出一次後，把它的「長相特徵」記成**樣板**（例如玉山帳單第一頁一定有某字串），下次直接規則判斷，不用再花 AI。

2. **歸屬（是誰的）**：把多條線索加權成一個信心分數：

   | 線索 | 強度 | 說明 |
   |---|---|---|
   | 卡號／帳號末四碼對到已登記的卡或帳戶 | 很強 | 第一次出現的卡就沒有這條 |
   | 帳單上的戶名對到成員的 `legalName` | 很強 | 要先填真實姓名（加密存） |
   | **用誰的密碼打開的** | 很強 | 帳單密碼通常是持卡人身分證字號，打得開＝就是他的 |
   | 轉寄信是從誰的信箱來的 | 中 | 二期才有 |
   | 誰丟進來的 | 弱 | Shark 常常幫 Apple 丟，所以只當參考 |

   - 分數 ≥ 0.9 → 直接歸屬，不問。
   - 0.6～0.9 → 先歸屬，但在 LINE 摘要裡寫「判斷為 Apple 的台新卡，不對請點這裡改」。
   - < 0.6 → **LINE 問一句**，Quick Reply 三個按鈕：「我的」「Apple 的」「共同」。
   - 新卡（末四碼沒看過）→ 問一句「這是新的卡：台新 *1234，要幫你建起來嗎？是誰的？」，答完自動建 CreditCard（結算日、繳費日直接從帳單讀，不用再去 LIFF 補三個欄位）。

3. **每次最多問一題**。一份文件同時有好幾個不確定時，依「歸屬 → 新卡／帳戶 → 個別可疑行」的順序問，前一題答完才問下一題；同一批丟進來的 10 份文件，問題合併成一則訊息，不要轟炸。

### 3.3 各種資料來源評估

> 準確度、時間是**估計值，尚未用真實帳單實測**，MVP 第一週要拿 Shark 家實際帳單驗證後修正。

| 來源 | 可行性（台灣） | 準確度（估） | Shark 每月操作時間（估） | 資安風險 | 建議 |
|---|---|---|---|---|---|
| **信用卡電子帳單 PDF** | 高。多數發卡行有電子帳單；有些是信件附 PDF、有些是信件內文或網頁版（例如台新說明數位帳單為加密形式、密碼規則寫在帳單內文［出處 1］；富邦提供自設帳單開啟密碼服務［出處 2］）。**密碼規則各家不同，不一定是身分證字號**，要逐家確認（未驗證全表） | 文字型 PDF：高（程式能驗「明細加總＝本期新增」）；掃描影像型：中 | 每張卡約 1 分鐘（轉傳到 LINE）；4～6 張卡約 5 分鐘 | 中：PDF 內有姓名、地址、卡號末碼、全部消費；密碼本身就是身分證字號 | **MVP 主力** |

**為什麼「每天自動抓 Gmail」不放 MVP、但放第二期第一項（MVP 一做完就接）**：
1. 自動抓的信最後還是要走同一條解析線（辨識、解密、解析、去重），先把這條線用 LINE 丟件做穩，自動抓只是多一個入口。
2. 全自動處理國泰這類加密 PDF，就**一定要系統記住密碼**（D3 選 B 或 D 並勾記住）。MVP 期間先用「每次問」跑一個月，Shark 和 Apple 再決定哪幾張卡要記。
3. 收信那一層有自己的工作：寄件人白名單、防假信、內文摘要解析、Gmail 轉寄驗證連結、每日合併詢問。獨立成一包比較好驗收。
4. MVP 期間手機上「郵件附件 → 分享到 LINE」只多 2 次點擊，不會卡住使用。
5. 如果 Shark 想一次到位，也可以把第二期第一項併進 MVP（多約 6 人日，見 7.1）。

### 3.4 PDF 密碼怎麼處理

**流程**：PDF 打不開 → 先用「這個家庭已記住的密碼」逐一試（如果 Shark 選擇記住）→ 打得開就順便得到「是誰的」→ 都不行才在 LINE 問：「這份台新帳單有密碼，請輸入密碼（通常是持卡人身分證字號，以帳單信件說明為準）」。

**輸入密碼的地方**：**不在聊天室打**（聊天紀錄會留在 LINE 和 webhook 記錄）。改成 LINE 回一個按鈕 → 開 LIFF 小頁面輸入 → HTTPS 送到後端 → 只在記憶體裡解密 PDF → 解完立刻丟掉。所有 log 對 `password` 欄位遮蔽。

**解密方式**：後端用 pdf.js（`pdfjs-dist` 支援帶密碼開檔並抽文字）在記憶體處理，不需要另裝 qpdf；若遇到 pdf.js 打不開的加密格式再評估 qpdf（要改 Dockerfile 加套件，注意 GCP 映像建置坑）。

**記不記密碼，四個選項**：

| 選項 | 做法 | 方便度 | 風險 |
|---|---|---|---|
| A. 每次都問，不保存 | 每份加密 PDF 都問一次 | 低：每月要輸入 4～6 次；Email 全自動不可能 | 最低：系統裡沒有身分證字號 |
| B. 記住，加密保存在後端 | 第一次輸入時勾「記住」；用 AES-256-GCM 加密，**金鑰放在主機環境的秘密管理（GCP Secret Manager），跟資料庫分開**；每個成員只存自己的 | 高：之後全自動（含 Email） | 中：資料庫和金鑰同時外洩時，身分證字號會外洩。因為密碼本身就是身分證字號，**保存密碼＝保存身分證字號** |
| C. 只記在使用者手機 | 存在 LIFF 頁面的瀏覽器儲存區，上傳時由手機端帶過來 | 中：LIFF 上傳免輸入；LINE 傳檔、Email 都用不到 | 低～中：換手機、清快取就沒了；手機被借走有風險 |
| D. 混合：預設 A，個別帳單勾選才 B | 每次問時多一個「記住這張卡的密碼」選項 | 中高 | 由使用者逐張決定 |

**建議：D**（預設不記，想全自動的卡才記）。真正要上 Email 全自動時，主要帳單再勾記住。另外：**Apple 的密碼只能由 Apple 本人輸入、本人決定要不要記**，Shark 丟 Apple 的帳單時，系統改問 Apple（LINE 推給 Apple：「Shark 上傳了一份你的帳單，需要你輸入密碼」）。

### 3.5 紙本存摺拍照：準確度與人工確認

- **拍法引導**：LINE 回覆附拍攝提示（平放、整頁、不反光、選原始畫質）。一次可以傳多頁，系統用 imageSet 和頁面上的日期順序排好。
- **解析**：Gemini 讀每一行的「日期／摘要／支出／存入／餘額」，回結構化 JSON。
- **餘額鏈驗算（程式算，不靠 AI）**：每一行都要滿足「上一行餘額 − 支出 ＋ 存入 ＝ 本行餘額」。
  - 全部對得起來 → 這頁大致可信（就算 AI 讀錯一個數字，鏈也會斷）。
  - 某一行斷了 → 只把**那一行**標成「待確認」，其他行照常入帳。
  - 第一行要接得上「上一次匯入的最後餘額」，接不上 → 可能中間漏拍一頁，提示「10/03 到 10/15 之間好像少一頁」。
- **人工確認**：LINE 推一則訊息「這頁 18 行，17 行自動核對 OK，1 行需要你看一下」→ 點進 LIFF 看到原照片裁切出來的那一行＋AI 讀到的數字，改數字或按確認。手機上一行一行滑，不要一整張表。
- **準確度（估計，未實測）**：AI 單純讀字可能有少量錯誤；加了餘額鏈驗算後，「錯了沒被發現」的機率應該很低，因為斷鏈一定會被抓到。真正的成本是「每頁要確認幾行」，MVP 第一週拿 Shark 家 3～5 頁實際存摺測，記錄每頁平均確認行數。
- **存摺摘要轉分類**：「ATM 提款」→ 轉到現金帳戶（不是支出）；「卡費」「信用卡款」→ 繳卡費（Transfer CARD_PAYMENT）；「房貸」「放款」→ 還貸款（拆本金／利息）；「薪資」→ 收入；其他交給規則＋AI 猜，猜不到放「待分類」。

### 3.6 冪等：同一份帳單重丟

三層防線：
1. **同一個檔案**：`sha256` 一樣 → 狀態直接標 DUPLICATE，LINE 回「這份 10 月台新帳單 11/02 已經匯入過了」。
2. **不同檔案、同一期**（例如重新下載的 PDF、截圖又丟一次）：`semanticKey`＝「類型＋銀行＋末四碼＋帳單日」一樣 → 不重複建帳單，只比對有沒有新的行。
3. **同一行**：每一行算指紋 `externalRef`＝hash(卡或帳戶, 消費日, 入帳日, 金額, 摘要正規化)，同一張卡已有同指紋就跳過。存摺照片因為 OCR 可能讀得不一樣，改用「日期＋金額＋餘額」當指紋（餘額讓指紋幾乎唯一）。

### 3.7 每份文件的處理狀態看得到

LIFF「丟件」分頁（手機優先）：
- 最上面三個數字：**處理中／待你確認／失敗**，點下去篩選。
- 每份文件一張卡片：縮圖、AI 認出的「台新信用卡 *1234／2026 年 10 月／Shark」、狀態標籤、入帳幾筆、跳過幾筆（重複）。
- 失敗一定有**白話原因＋下一步按鈕**：「密碼不對 → 重新輸入」「看不出是哪家銀行 → 手動選」「照片太糊 → 重拍」「這好像不是帳單 → 忽略」。
- LINE 端：每批處理完回一則摘要（Flex），不是每份一則。

### 3.8 每天自動從 Shark 和 Apple 的 Gmail 抓帳單（正式功能）

**目標**：兩人什麼都不用做，帳單信一到就自動解析入帳；沒把握的，每天合併成一則 LINE，**依帳戶歸屬問對的人**（Shark 的卡問 Shark、Apple 的卡問 Apple、共同帳戶問先設定的那位）。

#### 3.8.1 三種做法比較

| | (a) 伺服器用 Gmail API（OAuth） | (b) Gmail 篩選器自動轉寄到專屬收件地址 | (c) 本人帳號裝 Google Apps Script 定時送件 |
|---|---|---|---|
| 怎麼運作 | 兩人各授權一次，我們的伺服器每天用 refresh token 去讀兩人信箱 | 兩人各在 Gmail 建篩選器（寄件人＋主旨），符合的信自動轉寄到 `bills+家庭碼@money.ugomk.com`；Cloudflare Email Routing 收信 → Worker → 記帳後端 | 兩人各在自己 Google 帳號貼一份腳本、授權、設每日觸發；腳本只搜尋白名單信件，把信件內文與附件 POST 到記帳 API（帶家庭專屬上傳 token） |
| 要什麼權限 | 至少 `gmail.readonly`。官方分類：`gmail.readonly`、`gmail.metadata`、`gmail.modify` **全是受限範圍（Restricted）**［出處 12］。`gmail.metadata` 只能看標頭、**看不到內文**［出處 12］，讀不了帳單，不夠用 | 不需要任何 Google 權限 | 腳本用到 GmailApp，授權時 Google 會要求整個信箱的讀取權，但**權限留在本人的 Google 帳號裡**，我們伺服器拿不到 |
| 要不要過 Google 驗證 | 對外發布：受限範圍要過 OAuth 驗證，資料存到或經過伺服器還要做安全評估［出處 12］。只給自家用：官方「個人使用（少於 100 人）」可不驗證，登入時會看到「未經驗證的應用程式」警告，可以點過去［出處 13］ | 不用 | 不用（本人執行本人的腳本，會看到未驗證警告，點過去即可；Apps Script 是否另有限制官方頁面沒寫，**未驗證**） |
| 會不會過期 | **會**。發布狀態是「測試中」時，refresh token **7 天就失效**（只要的是姓名／email／個人資料以外的範圍）［出處 14］→ 每週要重新授權。改成「正式版」但不送驗證（個人使用）：官方 7 天規則是綁「測試中」，依文件推論不會 7 天失效，**未實測**。另外：**改 Google 密碼時，帶 Gmail 權限的 token 會失效**；6 個月沒用也會失效［出處 14］ | **不會**。轉寄設定一次就一直有效 | 基本上不會（授權留在本人帳號）；改腳本要新權限時要重新授權；**每日觸發器總執行時間上限 90 分鐘、單次 6 分鐘、讀信 2 萬次／天**（一般 gmail.com 帳號）［出處 15］，家庭用量遠低於此 |
| 設定難度 | 中：點連結 → Google 登入 → 點過警告 → 同意（每人 2 分鐘）；但我們要先建 GCP OAuth 專案 | 低～中：每人在 Gmail 設定加轉寄地址 → **Gmail 寄驗證連結到該地址，要點連結確認**［出處 16］（我們的收件端要把這封驗證信轉成 LINE 訊息給本人點）→ 建篩選器選「轉寄」。注意：用篩選器轉寄時，要關掉「全部轉寄」，只用篩選器轉［出處 16］ | 中～高：每人要打開 Apps Script、貼程式、按授權、設觸發器；Apple 可能需要 Shark 幫忙 |
| 我們握有什麼／外洩影響 | 伺服器握有**兩人整個信箱的讀取 token**。主機被入侵＝兩人所有信件（不只帳單）都可能被讀，**影響最大** | 只握有「被轉寄過來的那些帳單信」。收件地址外洩＝有人可以寄假帳單進來（用寄件人白名單＋驗證來源擋，見 3.8.3），**讀不到兩人的信箱** | 伺服器只握有「腳本送來的帳單」。上傳 token 外洩＝別人能往這個家庭丟假文件（只能寫、不能讀，可隨時換 token）；信箱權限不在我們手上 |
| 能不能只抓帳單、不碰其他信 | 技術上我們看得到所有信，只能靠程式「自我約束」只查白名單 | **可以**，篩選器在 Gmail 端過濾，其他信根本不會離開 Gmail | 腳本有權讀全部，但程式只搜白名單；程式碼放在本人帳號、本人看得到改得了 |
| 歷史回補 | 可以（搜過去一年） | **不行**（只轉寄新進的信；Gmail 沒有批次轉寄舊信） | **可以**（腳本搜過去 N 個月一次送完） |
| 每天幾點 | 我們排程 | 即時（信到就轉） | 觸發器排程（例如每天 07:00） |

**推薦：(b) 篩選器轉寄當每日自動來源；(c) Apps Script 只用一次做歷史回補（D8），回補完可以刪掉。不採用 (a)。**
- 理由：(b) 權限最小（我們碰不到其他信）、不會過期、不需 Google 驗證；唯一缺點是不能回補舊信，正好由 (c) 一次性補上。
- (a) 的問題是「為了讀帳單，伺服器要握著兩人整個信箱的鑰匙」，對家庭最敏感資料來說風險不成比例；而且測試狀態 7 天失效、改密碼失效，維護負擔最重。
- 如果之後 Apple 覺得設篩選器太麻煩，(c) 可以當 (b) 的替代方案，兩者都送進同一條解析線。

**另外說明**：主 agent 這次用 Claude Code 的 Gmail 連接器查 Shark 信箱，只是規劃用的一次性調查；它只在這台電腦開著 Claude Code 時能用、只連 Shark 本人帳號、拿不到附件內容，**不能當產品的每日來源**。Apple 的信箱目前沒有人查過，她的白名單要在設定時另外收集（3.8.2）。

#### 3.8.3 防假信

- 只收「轉寄自已登記的 Shark／Apple Gmail」的信（看轉寄標頭與 Gmail 加上的驗證結果）＋原寄件人在白名單。
- 有 S/MIME 簽章的（例如國泰帳單附 `smime.p7s`）驗證簽章，通過可加分；**簽章驗證的實作細節未驗證**，MVP 不靠它，只當加分。
- 從信件來的資料一律先進「待確認」層級的信心分數，跟其他來源（每日消費通知、存摺）對得上才升為自動入帳；對不上的不會直接影響淨資產。

#### 3.8.4 跟解析線、對帳怎麼接

- 收到的信 → 建 Document（channel=`EMAIL_FORWARD` 或 `GMAIL_SCRIPT`，`emailMessageId` 去重；同一封信 (b)(c) 都送進來也只算一次）→ **跟 LINE 丟件完全同一條解析線**（3.1 的 ①～⑥）。
- **內文摘要先記**：帳單信的 HTML 內文就有應繳金額、截止日，程式先用規則讀出來，建 CardStatement（狀態「只有摘要」）→ 繳費提醒馬上能用；PDF 解密成功後再補明細。PDF 打不開（沒記密碼）也不會整份卡住。
- **國泰每日「消費彙整通知」**：每封解析成「待入帳消費」（source=CARD_NOTICE），等月帳單進來時用 4.2 的規則對帳，對上了就合併；兩人自己有記的那筆也一起合併成一筆。
- **PDF 密碼**：照 3.4。國泰已確認是身分證字號（英文大寫）。要「每天全自動」就必須讓系統記住該卡密碼（D3）；沒記住時，系統先記內文摘要，並在每日詢問裡請**持卡人本人**開 LIFF 輸入一次密碼。

#### 3.8.5 每日合併詢問

- 每天一次（建議 21:00，跟現有的記帳 nudge 合併成同一則，避免一天收兩則），把當天所有「沒把握」的項目合成**一則** LINE Flex：
  - 問 Shark：Shark 名下帳戶／卡的問題
  - 問 Apple：Apple 名下的問題
  - 共同帳戶：問家庭設定的「共同帳戶負責人」（D15），沒設就問 OWNER
  - 歸屬不明（不知道是誰的）：兩人都問，**先回答的算數**，另一人的訊息自動更新成「已由 Shark 回答」
- 每題都是按鈕可以直接答（「我的／Apple 的／共同」「是同一筆／不是」「忽略這封」），需要打字的（密碼）一律開 LIFF。
- 當天沒有要問的就不發。

### 3.9 訂閱與系統帳單

Shark 有一大堆 Google、AI、雲端、SaaS 的訂閱，很多是**宇果公司的營運費用，但用 Shark 個人卡付**。這些錢從家庭的口袋出去，實際上應該由公司還，要能分開看。

#### 3.9.1 公司／家庭標記

資料模型（加在 2.6 的 Transaction 與新表）：
```
Transaction 加：
  bookTo          FAMILY | BUSINESS        // 這筆是家庭的錢還是公司的錢；預設 FAMILY
  reimburseStatus NONE | PENDING | CLAIMED | REIMBURSED   // 代墊公司費用的報帳進度
  serviceId?      → ServiceProfile         // 屬於哪個訂閱服務

ServiceProfile（每個家庭的「服務名冊」）
  id, familyId, name（例如「Vultr」「Google Workspace」）, vendorAliases[]（帳單上可能出現的寫法：VULTR HOLDINGS、GOOGLE*WORKSPACE…）
  defaultBookTo FAMILY | BUSINESS, ownerMemberId?, categoryId?
  isSubscription, cycle MONTHLY | YEARLY | USAGE（按量計費，如雲端主機）
  currency, lastAmount, lastChargedAt, nextChargeAt?, planName?
  lastUsedSignalAt?（最後一次看到「有在用」的跡象，見 3.9.2）
```

規則：
- **家庭全貌預設排除公司費用**：淨資產不受影響（錢確實從家庭帳戶出去了），但「家庭支出」「分類圓餅」「預算」都不算 `bookTo=BUSINESS` 的那幾筆。
- 另外算一個數字：**「代墊公司費用」**＝`bookTo=BUSINESS` 且還沒報帳（PENDING）的加總。在淨資產頁顯示成「公司欠家裡的錢」，算進資產的一行（應收），讓帳面完整（D16 選「列為代墊應收」時）。
- LIFF 有一頁「代墊公司費用」：依月份列出，可以全選匯出 CSV（日期、服務、方案、原幣金額、台幣金額、付款卡、收據檔），拿去跟公司報帳；報完標「已報帳」→ 公司匯錢回來那筆收入標「已歸墊」，自動把 PENDING 改成 REIMBURSED，那筆入帳也不算家庭收入。
- 判斷順序：服務名冊的預設 → 收據上有沒有打公司統編（光貿、關網發票可以讀到買方統編）→ 都沒有就放進每日合併詢問「Vultr US$24，公司還是家庭？」，答一次之後同服務自動照用。
- **同一筆對成一筆**：信用卡帳單會有一行「VULTR HOLDINGS 台幣 768」，收據信又有一封「Vultr Invoice US$24」。用 3.9.3 的規則對上之後合成一筆：**金額以卡帳單台幣為準**（實際扣的錢），**服務、方案、原幣金額、期間以收據為準**（例如「Vultr Cloud Compute 2 vCPU，2026-10 月」）。收據比帳單早到時，先建「待入帳」，等帳單來對。

#### 3.9.2 訂閱偵測與「全部訂閱清單」

偵測（全部程式算）：
- 有收據的：收據本身就有「方案、週期、下次扣款日」時直接用（Google、Zoom、Zoho 的收據通常有，未逐家驗證）。
- 沒收據的：卡帳單上同一個商家（經 vendorAliases 正規化）、原幣金額相近（±10%）、間隔 28～31 天連續 2 次以上 → 月繳；間隔 360～370 天 → 年繳；按量計費（雲端主機每月金額不同但每月都有）→ `USAGE`。
- AI 只做一件事：把「GOOGLE*CLOUD 9QX2」「PAYPAL *XXXX」這種帳單寫法翻成人看得懂的服務名，結果存進 vendorAliases，下次不用再問 AI。

「全部訂閱清單」頁（LIFF，手機優先）：
- 上方：**每月訂閱總額**（年繳的除以 12 攤進來；外幣用最近一次實際扣款的台幣金額）、其中公司／家庭各多少。
- 每一列：服務名、方案、月繳／年繳、原幣金額、台幣金額、付款卡、**下次扣款日**、公司／家庭。
- 提醒（併進每日或每月 LINE 摘要，不另發）：
  - **年繳到期前 14 天提醒**：「Zoom 年繳 US$149.9 將在 11/20 從國泰卡扣款，要續嗎？」
  - **價格變動**：同一服務原幣金額比上次高 5% 以上 →「GitHub 這個月 US$21 → US$25」。只看原幣，避免匯率波動誤報。
  - **長期沒用的提示**：這部分只能做「弱訊號」，因為系統不知道你有沒有在用。可用的跡象：該服務有沒有寄非帳單的使用通知、按量計費金額掉到最低消費。連續 3 個月沒有任何使用跡象 →「這幾個訂閱好像沒在用，要不要檢查一下？」，由人判斷，不自動做任何事。
  - **新出現的訂閱**：第一次偵測到某個週期扣款時通知一次。

#### 3.9.3 外幣收據與卡帳單台幣金額對帳

外幣收據（USD）和卡帳單（台幣）一定對不上整數，規則：
1. 換算：收據原幣金額 × **刷卡日前後 7 天內的匯率**（用公開的參考匯率，例如臺銀牌告即期賣出，資料來源實作時再定）＝預估台幣。
2. 國外交易服務費：台灣常見是 **1.5%**（一般說法：國際組織約 1%＋發卡銀行約 0.5%，美國運通不同；屬理財網站資訊，以各卡約定條款為準）［出處 17］。**只要商家或收單在國外、或用外幣結算，人在台灣刷也算海外交易**［出處 17］，所以網路訂閱幾乎都會有這筆。
   - 有的銀行把手續費併在同一行，有的另列一行「國外交易服務費」。兩種都要支援：另列的那一行掛回原交易（同一天、金額約為原交易 1.5%），不另算一筆支出，而是那筆訂閱成本的一部分。
3. 比對容許範圍：卡帳單台幣金額落在「預估台幣 × 0.97 ～ × 1.05」之間（下限給匯率波動，上限給 1.5% 手續費＋匯率），而且日期在收據日 0～5 天內（外幣交易入帳常常晚幾天）。
4. 對上之後記下**實際匯率**＝卡帳單台幣 ÷ 原幣（含手續費），下次同一服務的預估就用這個值，越對越準。
5. 退款：外幣退款可能以退款當天匯率入帳，台幣不會剛好等於原扣款；用「同服務、原幣金額相同、負數」配對，差額記成匯差，不另算收入或支出。
6. 一個月同服務扣兩次同金額（例如兩個帳號）：不自動合併，放待確認。

#### 3.9.4 財政部電子發票載具通知信能不能補消費明細？（未驗證）

- 已知：財政部官方寄件信箱是 `einvoice@einvoice.nat.gov.tw`，手機條碼完成 Email 驗證後可以開「消費發票彙整通知」等個人化功能［出處 18］。**通知信的實際內容（有沒有品項、店名、金額、是不是只有連結）沒找到官方說明，未驗證**。
- 如果信裡有「店名＋金額＋日期」：可以拿來對上刷卡或現金記帳，補上店名；有品項的話，可以把一筆「全聯 1,280」補成細項。價值很高，因為大部分實體店消費都會進載具。
- 如果信裡只有連結：不點連結（財政部提醒有大量冒名詐騙信［出處 18］），這條路就不通，改看官方「電子發票應用 API」能不能讓個人查自己的載具（出處 10，也未驗證）。
- 建議：第二期上線 Gmail 轉寄後，先把這類信收進來但**只存不解析**，拿 2～3 封實際信件看格式，再決定要不要做解析（列在第三期研究題）。光貿、關網這些加值中心寄的「開立通知」比較確定有明細，先做這些。

### 3.10 文字記帳與帳戶轉移（放進 P1）

**現況（55842f5）**：
- 聊天文字記帳已經有：一句記多筆、帶付款方式原文、商家進備註、未知付款方式會問要不要新增帳戶或卡。
- **文字不能指定日期**：`parseTransactionText` 沒有日期欄位，一律記成今天（收據和 PDF 才有日期）。
- **聊天文字不能建轉帳**：Transfer 表和 LIFF `POST /api/liff/transfers` 有，但只能帳戶轉帳戶、只能在 LIFF 填表。
- 沒有幣別、沒有「誰的」「公司的」。

#### 3.10.1 轉帳種類（都不算收支，只動餘額）

把 2.5 的 Transfer 擴充成：
```
Transfer
  kind  ACCOUNT        一般轉帳（台新 → 國泰）

  toAccountId? / toCreditCardId? / toLiabilityId?   （來源、目的各填一個，程式依 kind 檢查組合）

  undoneAt?      撤銷時間（撤銷不刪資料，留紀錄）
```

**會產生支出的只有這幾種（其他一律不算收支）**：

| 情況 | 不算收支的部分 | 另外產生的支出 |
|---|---|---|
| 還貸款 | 本金 → LOAN_REPAY 轉帳，沖剩餘本金 | **利息**（分類「貸款利息」）、**帳管費／違約金**（「手續費」） |
| 跨行轉帳、ATM 跨行提款 | 本金 | **手續費**（例如 15 元，分類「手續費」） |
| 繳信用卡 | 全額 | 無（若繳款有手續費才另記） |
| 定存提前解約 | 本金 | 無；**少拿的利息不是支出**，只是收入變少 |
| 定存到期 | 本金 | 利息是**收入**（分類「利息收入」） |
| 借出、收回、借入、還親友 | 全額 | 有約定利息才另記利息收入或支出 |
| 夫妻互轉 | 全額 | 無 |

#### 3.10.2 一句話建轉帳

**分工**：Gemini 只回「意圖＋欄位原文」，例如 `{intent:"TRANSFER", kind:"CARD_PAYMENT", from:"臺銀", to:"國泰卡", amount:24261, principal:null, interest:null, date:"", owner:""}`；**帳戶比對、金額檢查、本金＋利息是否等於總額，全部程式做**。Gemini 的金額只當解析結果，程式再從原句用規則抓一次數字比對，不一致就問。

| 使用者說 | 解析結果 |
|---|---|
| 「台新轉 5000 到國泰」 | ACCOUNT：台新 → 國泰（若「國泰」同時有銀行帳戶和信用卡 → 問一句） |
| 「從臺銀繳國泰卡 24261」 | CARD_PAYMENT：臺銀 → 國泰卡；找國泰卡最近一期未繳帳單，金額＝本期應繳 → 標已繳；小於 → 部分繳款；大於 → 溢繳，問一句 |
| 「領現金 3000」 | CASH_WITHDRAW：預設帳戶（或最常提款的那個）→ 現金；回卡片上寫出是從哪個帳戶，不對可改 |
| 「存 2 萬到將來定存」 | TIME_DEPOSIT：將來活存 → 將來定存；定存帳戶不存在 → 問「要建立『將來定存』嗎？」 |
| 「還房貸 18000（本金 12000 利息 6000）」 | LOAN_REPAY 12000 ＋ 一筆支出 6000（貸款利息）。程式檢查 12000＋6000＝18000，不等就問。只說「還房貸 18000」沒拆 → 依攤還表算出本期本金和利息，回卡片讓人確認 |
| 「借小明 5000」 | LEND：預設帳戶 → 新建（或找到）Liability(LENT, 對象「小明」) |
| 「小明還我 2000」 | COLLECT：Liability(小明) → 預設帳戶，剩 3000 |
| 「Apple 轉 1 萬給我」 | SPOUSE：Apple 的預設帳戶 → 說話者（Shark）的預設帳戶；**動到 Apple 的帳戶，要通知 Apple**（見下） |

- **權限**：文字轉帳的來源帳戶是別人的個人帳戶（例如 Shark 說「Apple 轉 1 萬給我」）時，照 D10 收緊後的規則，**不能直接扣 Apple 的帳戶**：先建「待 Apple 確認」，LINE 推給 Apple 一鍵確認；Apple 不回就只記在 Shark 這邊的收入側為「待確認」。（D18）
- 日期、歸屬、幣別規則跟 3.10.5 文字記帳相同。

#### 3.10.3 帳戶名稱模糊比對（程式做）

1. 先把說話者和句子正規化：全半形、台／臺、去掉「卡」「帳戶」「銀行」「的」等字，「我的」→ 說話者本人，「Apple 的」→ Apple。
2. 候選清單＝這個家庭**說話者看得到**的帳戶、卡、負債（依 6.2 可見範圍），每個都有 `name`、`institution`、`aliases[]`（使用者曾經用過的叫法，自動學）、末四碼。
3. 打分：完全相同 ＞ 別名命中 ＞ 機構名命中（「國泰」對到 institution＝國泰世華）＞ 末四碼（「1234 那張」）＞ 字串相似度。再用「歸屬」過濾：說「我的臺銀」只看說話者的；沒說是誰的，優先說話者本人，再來共同，最後別人的。
4. 結果：
   - 只有一個高分候選 → 直接用。
   - **兩個以上候選**（例如「國泰」有國泰世華活存和國泰卡；或 Shark、Apple 都有臺銀）→ Quick Reply 列出候選（最多 4 個）＋「都不是」。
   - **比不到** → Quick Reply「新增帳戶」「新增信用卡」「取消」（沿用現有 pending-account 流程）。
5. 點過的選擇存成別名，下次同一句不再問。

**確認卡**：建立後回一張 Flex：「臺銀 → 國泰卡　24,261　已沖 10 月帳單（應繳 24,261，已結清）」＋按鈕「撤銷」「改帳戶」「改金額」。
- **撤銷**＝標 `undoneAt`、把餘額和帳單已繳金額還原、連帶產生的利息或手續費支出一起撤；24 小時內可以一鍵撤銷，超過要到 LIFF。
- 撤銷用 postback 帶 transferId，並檢查按的人是建立者本人（或有權限的人）。

#### 3.10.4 跟「無腦丟件」對帳

手動記的轉帳，之後對帳單會再出現一次（臺銀存摺有「信用卡款 24,261」、國泰卡帳單有「繳款 24,261」）。規則：
- 對帳單匯入時，對每一行「看起來像轉帳／繳款」的（摘要含轉帳、卡費、繳款、ATM、定存、放款等，由規則判斷），先找**未對帳的手動 Transfer**：同一來源或目的帳戶、金額相同（跨行轉帳容許差一筆手續費金額）、日期差 0～3 天。
- 對上 → **不新建**，把手動那筆標 `RECONCILED`，記下對到哪個文件的哪一行（`documentId` 與 `externalRef`）；手動那筆的日期改成銀行實際日期，原日期留在紀錄。
- 一次轉帳會在**兩邊**對帳單都出現（臺銀扣款＋國泰卡繳款入帳）：兩邊各自對到同一筆 Transfer，第二次出現時認出「這筆已經對過一邊了」，不會建第二筆。
- 手動沒記、對帳單才出現 → 自動建 Transfer（source=STATEMENT），一樣不算收支。
- 手動記了、對帳單期間已涵蓋卻找不到 → 標「對帳單上找不到」，放每日合併詢問（可能記錯帳戶或日期）。
- LIFF 帳戶頁每筆轉帳顯示「已對帳」或「未對帳」。

#### 3.10.5 文字記帳補強（現有能力全部保留）

保留：一句多筆、付款方式、商家進備註、未知付款方式詢問、記帳後 Quick Reply 改分類／改共同個人／刪除。

補上：

| 能力 | 例子 | 做法 |
|---|---|---|
| 指定帳戶或卡（已有，補強比對） | 「刷國泰卡午餐 120」 | 付款方式原文改走 3.10.3 的模糊比對；兩個候選時 Quick Reply |
| 指定日期 | 「昨天 晚餐 300」「10/3 加油 1200」「上週五 電影 600」 | Gemini 只回日期原文；**程式用台北時區換算**（今天、昨天、前天、星期幾、M/D、YYYY/M/D）。沒寫年份時，換算出來在未來就往前推一年。換算不出來 → 記成今天並在回覆標出「日期是今天，要改嗎」 |
| 一句多筆＋不同日期 | 「昨天早餐 80，今天午餐 120」 | 每一筆各自帶日期 |
| 指定歸屬人 | 「幫 Apple 記 美髮 1500」「Apple 的午餐 150」 | 記錄者仍是說話者，**付款人／歸屬人**改成 Apple；分帳、個人支出照 Apple 算 |
| 公司費用 | 「公司 Zoom 15.99 美金」「公司 計程車 350」 | 有「公司」字樣 → `bookTo=BUSINESS`，進「代墊公司費用」（3.9.1）；或服務名冊裡 Zoom 預設就是公司 |
| 外幣 | 「Zoom 15.99 美金」「日本 拉麵 1200 日圓」 | 存原幣＋原幣金額；先用參考匯率估台幣（標「預估」），卡帳單進來後依 3.9.3 改成實際台幣 |
| 混在一起 | 「昨天刷國泰卡 公司 Zoom 15.99 美金，跟 Apple 吃晚餐 800」 | 拆兩筆，第一筆公司＋外幣＋國泰卡＋昨天，第二筆家庭共同 |
| 同一句含轉帳和消費 | 「領現金 3000，然後午餐 120 用現金」 | 拆成一筆轉帳＋一筆支出 |

回覆的確認卡把程式最後判斷的每個欄位都寫出來（日期、帳戶、歸屬、公司或家庭、原幣與預估台幣），不對就點按鈕改。

## 4. 重複與對帳

### 4.1 同一筆消費出現三次的問題

例：Shark 在全聯刷台新卡 1,280 元。
1. 當天拍收據記帳 → Transaction A（PHOTO，可能拆成 5 個品項，掛同一個 receiptGroupId）
2. 月底台新帳單 → 一行「全聯 1,280」
3. 下個月銀行存摺 → 一行「信用卡款 台新 32,450」（整期卡費，不是單筆）

**處理規則**：
- 第 1 和第 2 是**同一筆消費** → 合併，只算一次。
- 第 3 是**繳卡費** → 不是支出，是 Transfer（銀行 → 台新卡），同時把那一期 CardStatement 標成已繳。

### 4.2 比對演算法（全部程式算）

帳單上每一行，去找「同一張卡（或同一個付款方式未指定）、還沒被配對過」的既有交易：

| 條件 | 規則 |
|---|---|
| 金額 | 完全相同；或 receiptGroupId 群組加總相同（收據拆品項的情況）；外幣交易照 3.9.3（匯率＋約 1.5% 國外交易服務費，容許 0.97～1.05 倍） |
| 日期 | 帳單消費日 與 記帳日 相差 0～3 天（記帳可能晚記；海外消費可能差更多，放寬到 7 天但降低分數） |
| 商家 | 帳單摘要 與 記帳備註 的相似度（正規化：去空白、全半形、常見前綴如「全聯福利中心」→「全聯」）只當加分，不當必要條件 |

- 分數高、只有一個候選 → 自動合併：**金額以帳單為準**（實際扣的錢），**分類、備註、品項以手記的為準**（人記的比較懂）。
- 有兩個以上候選（例如同天兩筆一樣 120 元）→ 放「待確認」，LIFF 讓人選。
- 帳單有、手記沒有 → 新建交易（source=STATEMENT），AI 只負責猜分類。
- 手記有、帳單沒有（而且帳單期間已涵蓋那天）→ 不刪，標「帳單上找不到」，可能是記錯卡、或是現金其實沒刷卡。
- 合併可以「拆回來」：每次合併記錄在 `matchGroupId`，LIFF 點一下可以還原。

### 4.3 「不是支出」清單（寫死在規則裡，不給 AI 判斷）

- 繳卡費（帳單「上期繳款」、存摺「卡費／信用卡款」）→ Transfer CARD_PAYMENT
- 帳戶互轉、ATM 提款到現金 → Transfer ACCOUNT
- 還貸款本金 → Transfer LOAN_PRINCIPAL（利息另記支出）
- 存入定存、買基金股票 → Transfer（資產換資產）
- 信用卡退款、取消交易 → 沖銷原交易，不是收入
- 夫妻之間轉錢 → 家庭層級是 Transfer，不算收入也不算支出

### 4.4 帳單層級對帳

每份信用卡帳單匯入後程式驗算：「上期應繳 − 已繳 ＋ 本期新增消費 − 退款 ± 調整 ＝ 本期應繳」。對不起來 → 整份標「待確認」，通常是 AI 漏讀一行。

## 5. AI 全貌：要產出什麼、誰來算

**鐵則：數字一律程式算（SQL／TypeScript），Gemini 只做三件事——辨識與解析文件、猜分類、把程式算好的數字用白話講出來。** Gemini 回的任何數字都不直接寫進報表，只能當「解析結果」，經過程式驗算（加總、餘額鏈）才入帳。

| 產出 | 誰算 | 說明 |
|---|---|---|
| 淨資產走勢（月） | 程式 | NetWorthSnapshot 折線圖；家庭總和＋每人各一條 |
| 現金流（月收入、支出、存下多少、儲蓄率） | 程式 | 排除所有 Transfer |
| 負債總覽＋還清時間表 | 程式 | 每筆貸款的攤還表（本息平均／本金平均／寬限期）、預計還清日 |
| 提前還款試算 | 程式 | 「每月多還 5,000 / 一次還 30 萬」→ 少付多少利息、提早幾個月；比較「拿去還房貸 vs 放定存」只列數字，不給投資建議 |
| 固定支出／訂閱偵測＋全部訂閱清單 | 程式為主 | 規則見 3.9.2：收據週期優先，否則同商家、原幣金額相近、間隔 28～31 天（或 360～370 天）；年繳到期前提醒、價格變動、長期沒用提示。AI 只負責把「GOOGLE*CLOUD」這類寫法翻成服務名 |
| 代墊公司費用 | 程式 | `bookTo=BUSINESS` 未報帳加總、可匯出報帳（3.9.1） |
| 異常消費 | 程式 | 單筆超過該分類過去 6 個月平均＋3 倍標準差、同卡短時間重複扣款、海外小額測試扣款 → 提醒 |
| 每月 LINE 摘要（升級現有月報 Flex） | 程式算＋AI 寫一段話 | 淨資產變化、存了多少、最大三個支出變化、下個月要繳的卡費與貸款；AI 只把程式給的數字寫成 3 句話 |
| 問答「我們今年保險花多少」 | AI 解讀問題→程式查 | Gemini 把問題轉成**固定格式的查詢條件**（期間、分類、成員、帳戶、彙總方式），由程式查資料庫算出數字，再交給 Gemini 寫成一句話。**不讓 AI 寫 SQL**、不把整包明細丟給 AI。查詢一律套用提問者的可見範圍 |
| 分類 | AI | 沿用現有 Gemini 分類，分類清單鎖死（enum） |

## 6. 隱私與資安

### 6.1 必修：記帳簿 API 沒有驗證身分（上線中的既有問題）

- 現況：`server/src/routes/liff.ts` 每支 API 都用 `req.header('x-line-user-id')` 認人，前端 `web/lib/api.ts` 直接把 userId 放在 header 送出，**後端沒有驗證這個 userId 是不是本人**。後端 `line-family-ledger.zeabur.app/api/liff/*` 也可以直接打。任何人只要拿到某個家庭成員的 LINE userId，就能讀寫那個家庭的帳。
- 修法：LIFF 前端改送 `liff.getIDToken()`（或 access token），後端用 LINE 官方驗證端點驗證後取出 userId，`x-line-user-id` 一律不採信。後端直連網址也要關掉或只允許前端代理。
- **進度**：修正已在分支 `fix/liff-id-token-verify`（`7e3a564`，新增 `server/src/lib/liff-auth.ts`＋測試，移除 `x-line-user-id` 後門），尚未併入 `integ/ledger-1106`、尚未上線；P1 以此為基底開工（7.2）。
- 這是**財務中樞的前置條件**，任何新資料表上線前必須先修並部署（P0）。建議即使不做中樞也該單獨排一次部署修掉。

### 6.2 夫妻各自可見範圍

- 每個帳戶、卡、負債都有 `ownerMemberId`＋`visibility`（2.1）。
- 交易的可見範圍跟著付款帳戶／卡走：掛在 Apple「僅總額」帳戶的消費，Shark 看得到月總額，看不到每一筆。
- 家庭報表（淨資產、現金流）是否包含「僅總額」帳戶：**包含總數**；`OWNER_ONLY` 不包含（見 D2）。
- 編輯權限：別人的個人帳戶交易**只有本人能改、能刪**；共同的大家都能改。現在的程式是「同家庭任何人都能改任何一筆」，要收緊（D10）。
- 文件：誰的帳單只有本人（和共同帳戶的成員）看得到原檔與明細。
- AI 問答與 LINE 月報一律依提問者／收件者的可見範圍過濾；推給 Apple 的月報不能出現 Shark 的 OWNER_ONLY 資料。

### 6.3 欄位加密與「根本不存」

- **根本不存**：卡號全碼、帳號全碼（只存末四碼）、網銀帳密、CVV、身分證字號（除非 D3 選擇記住密碼）。
- **應用層加密（AES-256-GCM，金鑰在 Secret Manager）**：成員真實姓名、記住的帳單密碼、原始檔案（若保存）、解析結果中的地址。
- 資料庫本身：雲端主機硬碟加密（GCP 預設）＋連線 TLS。

### 6.4 原始 PDF／照片保存多久（D4）

- 建議：**原檔加密保存 30 天**（給「重新解析」和人工確認看原圖用），之後自動刪除，只留解析後的資料和 sha256（冪等用）。
- 存摺照片在「待確認」期間保留，確認完 30 天後刪。

### 6.5 帳單密碼絕不落地（除非明確選擇記住）

- 只透過 LIFF 表單輸入，不在聊天室；後端只在記憶體使用；log 遮蔽；不進錯誤追蹤、不進資料庫、不進備份。
- 選擇記住時：只存加密值，記錄「誰、何時、哪張卡」同意記住；可以在 LIFF 一鍵全部刪除。

### 6.6 送給 Gemini 之前

- **必須用付費層**。Google 條款：免費層送出的內容會被拿去改進產品、可能有人工審閱，並明講不要送敏感個資；付費層不拿 prompt／回應改進產品，只短期保存做濫用偵測［出處 11］。目前專案用的 GEMINI_API_KEY 是哪一層**未驗證**（D1）。
- **文字型 PDF：先在後端抽文字、遮罩再送**：卡號（13～19 碼數字）、帳號（10～16 碼）、身分證字號（英文＋9 碼）、手機、地址、姓名替換成代號（`[卡號末4:1234]`、`[戶名A]`）。
- **照片／掃描檔沒辦法先遮罩**（AI 要看圖才讀得出字），只能靠付費層條款保護，這點要讓 Shark 知道（D1）。
- 送出的只有「解析需要的那一份文件」，不附家庭其他資料。

### 6.7 備份

- 每日資料庫備份，**備份檔加密**（用 age 或 GPG 公鑰加密後才上傳到 R2 等異地儲存），保留 30 天；每季做一次還原演練。
- 備份不包含原始檔案儲存區以外的任何密碼明文（本來就沒有）。

### 6.8 稽核

- 記錄「誰看了誰的帳單原檔」「誰改了誰的交易」「誰記住／刪除了密碼」，LIFF 可查。

## 9. 推薦 MVP（一頁版）

**做什麼**：P0 資安前置＋P1 資產負債骨架＋P2 無腦丟件（電子帳單 PDF＋存摺照片，從 LINE 和 LIFF 丟）＋文字記帳補強與一句話建轉帳，約 33.5 人日。

**做完後 Shark 每月的操作（估）**：
1. 收到帳單信 → 附件分享到 LINE「宇果記帳」（每張卡約 1 分鐘）
2. 存摺補登後拍照傳 LINE（每本約 3～5 分鐘，含確認 1～2 行）
3. 回答 LINE 上偶爾一兩題「這是誰的」
4. 打開記帳簿「全貌」分頁看淨資產、負債時間表、本月存了多少

**合計約 10～15 分鐘／月**；第二期「每天自動抓 Gmail」上線後，信用卡與電子對帳單那一段降到接近 0，只剩紙本存摺拍照和回答每日合併詢問。

**開工前**：D1～D18 已全部決定（11-05）；P1 從 `fix/liff-id-token-verify`（7e3a564）開工；P2 開工前要先完成 Shark 待辦 S1（Gemini 付費層）與 P0-2／P0-3；deploy-ops 確認記帳服務最終部署平台與秘密管理位置；準備 Shark 家實際帳單各一份（每家銀行一份）當測試樣本，**只在本機或測試環境跑，不碰正式資料**。
